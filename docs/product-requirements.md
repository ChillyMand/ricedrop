# 网页版局域网文件传输助手产品需求文档

文档版本：1.0

产品阶段：MVP 设计确认  
部署目标：Cloudflare Workers 免费计划

## 1. 产品概述

本产品是一款无需安装客户端的网页版局域网文件传输工具。两台设备通过短期配对码建立临时会话，连接成功后通过 WebRTC DataChannel 在局域网内点对点传输文件。

Cloudflare 仅负责托管网页、维护配对房间和交换 WebRTC 信令。文件内容不得上传至 Worker、Durable Object、R2 或任何公网中继服务。如果无法建立局域网点对点连接，产品应终止传输并明确告知用户，不得自动切换为公网转发。

## 2. 产品目标

### 2.1 核心目标

- 用户无需下载或安装软件，使用现代浏览器打开网址即可使用。
- 两台设备通过同一个配对码快速建立连接。
- 一次配对建立双向会话，双方均可发送和接收文件。
- 同一会话可连续传输多个文件，无需重复配对。
- 文件只通过设备间的 WebRTC 连接传输，不经过公网服务器。
- 支持桌面端与移动端之间传输。
- MVP 可运行在 Cloudflare Workers 免费计划内。

### 2.2 非目标

MVP 不包含以下能力：

- 不扫描局域网 IP 或自动列出附近设备。
- 不使用公网服务器中转文件。
- 不提供云端文件存储、历史文件下载或离线收件箱。
- 不支持第三台设备加入同一个会话。
- 不承诺跨网段、访客 Wi-Fi、开启客户端隔离的网络可以连接。
- 不提供账号体系、联系人和永久设备绑定。
- 不提供关闭页面后的断点续传。
- 不提供文件夹目录结构传输；用户可先压缩文件夹后发送。

## 3. 目标用户与场景

### 3.1 目标用户

- 希望在手机和电脑之间快速传文件的个人用户。
- 家庭、小型办公室和工作室内的多设备用户。
- 不方便或不愿安装专用文件传输软件的临时用户。

### 3.2 典型场景

1. 手机与电脑连接同一个 Wi-Fi，用户将手机照片发送至电脑。
2. 两台办公电脑位于同一局域网，双方互传多个大型文件。
3. 用户先从电脑向手机发送文件，随后在同一会话中由手机反向发送文件。

## 4. 核心产品原则

### 4.1 配对码负责相遇，不承载连接地址

配对码是 Cloudflare 信令服务中的临时房间标识，不编码设备局域网 IP。浏览器不能像原生应用一样在固定 IP 和端口上启动文件服务，仅交换 `192.168.x.x` 地址不足以建立浏览器间连接。

双方进入同一个房间后，通过信令服务交换 WebRTC Offer、Answer、ICE candidates 和必要的重协商消息。浏览器的 WebRTC 引擎负责建立加密的数据通道。

### 4.2 配对角色不等于传输角色

创建配对码的一方是初始 Offer 方，输入配对码的一方是初始 Answer 方。该区分仅用于建立连接。WebRTC DataChannel 建立后，双方地位对等，均可发送、接收、拒绝或取消文件。

### 4.3 文件绝不经过公网中继

- WebRTC 配置不得包含 TURN 服务。
- 严格局域网模式下不配置 STUN，即 `iceServers: []`。
- 建连完成后检查实际选中的 ICE candidate pair。
- 检测到 `relay` candidate 时立即终止连接。
- 无法建立直接连接时不得回退至 Worker、R2、TURN 或其他中继。
- 服务端不得实现文件上传或文件转发接口。

## 5. 用户流程

### 5.1 创建会话

1. 用户 A 打开产品首页。
2. 用户 A 点击“创建配对码”。
3. 系统创建一个三位数字配对码，例如 `527`。
4. 页面提示配对码有效时间，并允许复制配对码。
5. 用户 A 等待另一台设备加入。

### 5.2 加入会话

1. 用户 B 打开同一网址。
2. 用户 B 输入用户 A 提供的三位配对码。
3. 系统校验房间是否存在、是否过期、是否已被占用。
4. 用户 A 收到加入请求，界面展示用户 B 的临时设备名称。
5. 用户 A 点击“允许连接”或“拒绝”。
6. 允许后，双方交换 WebRTC 信令并尝试建立直接连接。
7. 建连成功后，双方进入文件交换界面。

### 5.3 发送文件

1. 任意一方点击“选择文件”或将文件拖入页面。
2. 用户可一次选择一个或多个文件。
3. 系统向对方发送文件名称、大小和类型等元数据。
4. 对方选择接受或拒绝。
5. 接受后，文件按队列依次传输。
6. 双方界面实时显示文件进度、速度、已传大小和状态。
7. 一个文件完成后自动开始队列中的下一个文件。
8. 队列完成后，双方仍保持连接，可继续互传文件。

### 5.4 结束会话

出现以下任一情况时结束会话：

- 任意一方点击“断开连接”。
- 任意一方关闭或刷新页面，且在恢复期限内未重连。
- 网络连接永久中断。
- 双方长时间无操作并确认结束会话。

会话结束后，Durable Object 清除房间状态和连接附件。已失效的配对码不能再次使用。

## 6. 配对码与会话生命周期

### 6.1 状态定义

| 状态 | 含义 | 超时规则 |
|---|---|---|
| `waiting` | 创建方等待第二台设备加入 | 3 分钟无人加入则失效 |
| `approval` | 加入方已提交请求，等待创建方确认 | 60 秒未确认则返回等待状态 |
| `negotiating` | 双方正在交换 WebRTC 信令 | 60 秒未建连则失败 |
| `connected` | WebRTC 已连接，可双向传文件 | 不受配对码 3 分钟限制 |
| `reconnecting` | 连接短暂中断，尝试重新协商 | 最长保留 60 秒 |
| `closed` | 会话已结束 | 立即清理临时状态 |

### 6.2 过期逻辑

- 三分钟有效期只限制“等待第二台设备加入”的阶段。
- 第二台设备加入并被创建方接受后，服务端立即删除配对码到房间的映射，并停止接受新设备。
- 配对成功时为双方签发至少 128 位强随机 Session ID；后续信令和传输会话只识别 Session ID，不再依赖三位配对码。
- 正在进行的文件传输不受配对码有效期影响，可持续数小时。
- 配对成功后保留信令 WebSocket，用于状态同步和必要的 ICE restart。
- 传输结束不会自动断开会话，用户仍可继续发送文件。
- 会话关闭后配对码永久失效；再次使用必须创建新配对码。

### 6.3 配对码安全规则

- 使用加密安全随机数生成三位数字码，范围为 `000` 至 `999`，显示时必须保留前导零。
- 服务端仅保存配对码的不可逆摘要，不记录明文码。
- 同一配对码最多连接两台设备。
- 创建方确认前不得开始 WebRTC 信令交换。
- 加入成功后立即锁定房间，拒绝第三方加入。
- 同一 IP 每分钟最多提交 5 次配对请求，连续输错 5 次后冷却 10 分钟。
- 对创建操作实施 IP 级速率限制，同一 IP 同时最多保留 3 个等待房间。
- 同一个配对码同一时间只允许存在一个待确认请求，防止请求覆盖和竞态加入。
- 生成配对码时必须避开仍处于有效期内的代码；全部代码空间接近占满时停止创建并提示稍后重试。
- 日志不得记录明文配对码、完整 SDP 或 ICE candidate 内容。

## 7. 多文件与双向传输

### 7.1 会话能力

- 一次配对建立一个双向连接。
- 双方可在同一会话中不限次数地发起文件发送。
- 每次可选择多个文件。
- 每个方向维护独立传输队列。
- 每个方向内部默认串行传输文件。
- MVP 允许 A→B 与 B→A 两个方向同时各传输一个文件。

### 7.2 文件协议消息

控制消息使用 JSON，文件内容使用二进制帧。核心消息类型包括：

- `session-ready`：会话已准备完成。
- `file-offer`：发送文件名称、大小、MIME 类型、文件 ID 和分块大小。
- `file-accept`：接受指定文件。
- `file-reject`：拒绝指定文件。
- `file-chunk`：传输指定文件的数据块。
- `file-complete`：发送方已完成文件发送。
- `file-verified`：接收方完成大小或摘要校验。
- `file-cancel`：任一方取消指定文件。
- `transfer-error`：报告文件级错误。
- `session-close`：主动结束会话。

### 7.3 分块与流量控制

- 文件按固定大小切块，初始建议为 64 KiB。
- 发送端根据 DataChannel 的 `bufferedAmount` 和 `bufferedAmountLowThreshold` 控制发送速度。
- 不允许一次性将完整大文件读入内存。
- 每个数据块携带文件 ID 和顺序编号。
- 文件完成后校验接收字节数；摘要校验作为增强项，应避免因整文件摘要导致移动端内存压力。

## 8. 功能需求

### 8.1 首页

- 展示产品用途和“文件仅在设备间传输”的隐私说明。
- 提供“创建配对码”主按钮。
- 提供三位配对码输入框和“加入”按钮。
- 输入框自动忽略空格和连字符。
- 展示浏览器兼容性与同一局域网提示。

### 8.2 等待与确认

- 展示配对码及剩余有效时间。
- 支持一键复制配对码。
- 显示加入设备的临时名称和浏览器类型。
- 创建方必须明确允许或拒绝连接。
- 拒绝后房间继续等待，剩余有效期不重置。

### 8.3 连接状态

- 显示“正在建立局域网连接”。
- 区分信令已连接、WebRTC 正在协商和局域网直连成功。
- 连接成功后显示对方设备名称。
- 建连失败时明确说明文件没有上传，也不会改用公网中转。

### 8.4 文件交换界面

- 支持文件选择和桌面端拖放。
- 展示发送队列与接收队列。
- 展示文件名、大小、方向、进度、速度和状态。
- 接收方可逐个接受或拒绝文件。
- 支持取消正在传输或等待中的文件。
- 支持队列完成后继续添加文件。
- 提供明确的“断开连接”操作。

### 8.5 下载与保存

- 小文件可在接收完成后生成 Blob 并触发浏览器下载。
- 支持 File System Access API 的浏览器应优先提供流式写入，以降低大文件内存占用。
- 不支持 File System Access API 的浏览器必须说明大文件可能受到设备内存限制。
- 未经用户确认不得自动覆盖同名文件。

## 9. 系统架构

### 9.1 Cloudflare 组件

| 组件 | 职责 |
|---|---|
| Workers Static Assets | 托管 HTML、CSS、JavaScript 和图标 |
| Worker | 创建/加入房间接口、WebSocket 升级、输入校验与限流 |
| Durable Object | 每个房间的单点状态、两端 WebSocket 与信令转发 |
| WebSocket Hibernation API | 空闲时休眠房间，降低免费额度消耗 |

MVP 不使用 R2、D1、KV、Queues 或 TURN。

### 9.2 房间模型

每个房间由独立 Durable Object 管理，至少维护：

- 房间状态；
- 创建时间与过期时间；
- 创建方 WebSocket 及序列化附件；
- 加入方 WebSocket 及序列化附件；
- 双方临时设备信息；
- 最近活动时间；
- 建连和重连状态。

不存储文件名称历史、文件内容、完整 SDP 或长期设备标识。

### 9.3 客户端组件

- 配对控制器：创建、加入和房间状态管理。
- 信令客户端：维护 Cloudflare WebSocket 和消息顺序。
- WebRTC 连接管理器：Offer/Answer、ICE、DataChannel 和重连。
- 传输协议层：文件元数据、分块、队列和确认消息。
- 文件读写层：分块读取、流式保存和浏览器降级。
- 视图状态层：连接、进度、错误和操作反馈。

## 10. 安全与隐私

- 所有网页和信令必须使用 HTTPS/WSS。
- WebRTC DataChannel 使用浏览器提供的 DTLS 加密。
- 禁用 TURN 和服务器文件中转。
- 加入方需经创建方确认。
- 配对码短期有效、单次使用、最多两台设备。
- 所有接口校验消息类型、大小、房间状态和发送者角色。
- 限制 SDP、ICE 和控制消息体积，防止滥用 Durable Object 内存。
- 设备名称必须转义后显示，防止脚本注入。
- 不使用用户输入拼接 Durable Object ID；先规范化并计算摘要。
- 生产日志只保留错误类型、耗时和匿名会话标识。
- 页面应明确说明信令元数据会经过 Cloudflare，但文件内容不会经过服务器。

## 11. 异常与边界处理

| 场景 | 产品行为 |
|---|---|
| 配对码不存在或已过期 | 提示重新核对或创建新配对码 |
| 房间已有两台设备 | 拒绝加入，不透露房间成员信息 |
| 创建方拒绝 | 加入方收到拒绝提示，双方不交换 WebRTC 信令 |
| 两设备不在可直连网络 | 建连失败，明确不使用公网中转 |
| Wi-Fi 开启客户端隔离 | 提示网络阻止设备间通信 |
| 页面短暂切入后台 | 保持连接；移动端系统终止页面时按断线处理 |
| 传输中网络波动 | 暂停进度并尝试在 60 秒内重新协商 |
| 单个文件传输失败 | 标记该文件失败，不删除其他等待文件 |
| 对方取消文件 | 立即停止该文件分块发送并释放资源 |
| 对方关闭页面 | 终止当前传输并提示连接已断开 |
| 浏览器内存不足 | 终止当前文件并建议使用支持流式保存的桌面浏览器 |
| 免费额度耗尽 | 新请求失败时展示服务暂时不可用，不允许绕过安全检查 |

## 12. 兼容性范围

MVP 优先支持最新两个主要版本的：

- Chrome 桌面版与 Android 版；
- Edge 桌面版；
- Safari macOS 与 iOS 版；
- Firefox 桌面版。

不同浏览器对 File System Access API 和移动端后台运行的支持不同。WebRTC 连接和基础 Blob 下载属于核心兼容目标；超大文件流式保存属于渐进增强能力。

## 13. 性能与容量要求

- 首页静态资源应尽量小，首次可交互目标为普通网络下 2 秒内。
- 配对房间创建目标响应时间小于 1 秒。
- 第二台设备加入后，应在正常网络下 5 秒内完成 WebRTC 建连。
- 文件速度主要受局域网、设备存储和浏览器实现影响，服务端不设文件大小限制。
- 客户端不得因文件总大小线性增加内存占用。
- Durable Object 必须采用 Hibernation WebSocket API，不使用定时器维持常驻。

## 14. MVP 验收标准

### 14.1 配对

- 用户能够创建三位配对码，包括带前导零的代码。
- 另一台设备能够通过正确配对码申请加入。
- 错误、过期和已占用配对码均有明确提示。
- 创建方拒绝前，双方不得建立 WebRTC 连接。
- 创建方接受后，配对码不能被第三台设备使用。

### 14.2 局域网连接

- 同一普通家庭 Wi-Fi 下的两台兼容设备可以建立 WebRTC DataChannel。
- 配置中不存在 TURN 服务。
- 检测到中继连接时必须断开。
- 无法直连时文件不会上传到 Cloudflare。

### 14.3 文件传输

- 任意一方都能发送文件。
- 一次选择多个文件后能够依次传输。
- 双方可以在同一会话中反复互传文件。
- 文件进度、速度、完成、失败和取消状态正确显示。
- 接收文件大小与发送文件大小一致。
- 一个文件失败不会导致等待队列中的状态丢失。

### 14.4 生命周期

- 等待加入超过3分钟的配对码失效。
- 已建立连接的传输不会在3分钟时被中断。
- 传输完成后仍能继续添加文件。
- 主动断开或页面关闭后，房间状态能被清理。
- WebSocket 休眠恢复后仍能识别两端连接身份。

## 15. 后续版本候选能力

- 二维码分享配对码。
- 支持拖入文件夹并保留目录结构。
- 基于分块确认的断点续传。
- 可配置的文件摘要校验。
- 已信任设备的快速重连。
- 局域网私有化部署版本。
- PWA 安装与系统分享菜单集成。
- 多设备临时房间，但仍禁止服务器中转文件。

上述能力不属于 MVP，只有在基础双向多文件传输完成并验证稳定性后再评估。
