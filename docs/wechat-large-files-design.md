# 微信浏览器拦截与 10GB 大文件传输设计

> 历史设计记录。当前兼容性和大文件边界以根目录 README、当前代码和测试为准。

## 目标

在不改变现有小文件体验的前提下：

- 禁止微信内置浏览器创建、加入或传输文件，并引导用户使用系统浏览器。
- 在桌面版 Chrome、Edge 中支持单文件最大 10GB 的局域网直传。

## 产品边界

- `512 MB` 以下为小文件，继续使用现有内存接收和自动下载/系统分享流程。
- `512 MB` 及以上、`10 GB` 以下为大文件，只允许桌面版 Chrome 或 Edge 接收。
- 超过 `10 GB` 的文件在发送前阻止并明确提示。
- Safari、Firefox和移动端收到大文件请求时不开始传输，提示改用电脑端 Chrome 或 Edge。
- 文件内容仍不经过服务器或公网中转。

## 微信浏览器

通过 User-Agent 中的 `MicroMessenger` 识别微信内置浏览器。识别后显示阻断页：

- 标题：`请在系统浏览器中打开`
- 说明微信内置浏览器不支持可靠的局域网文件传输。
- 提供 `复制链接` 按钮。
- Android 可尝试打开系统浏览器；失败时提示通过微信右上角菜单选择浏览器打开。
- 阻断状态下不调用创建房间、加入房间或 WebRTC 接口。

## 双模式接收

### 小文件

保持现有协议和保存流程：接收分片到内存，完成后生成 `File`，桌面自动下载，移动端使用系统分享面板并保留再次下载能力。

### 大文件

发送方发送文件信息后，接收方必须先通过用户点击选择保存位置。获得 `FileSystemFileHandle` 后创建 `FileSystemWritableFileStream`，再发送接受消息。

每个到达的分片按顺序直接写入磁盘，不保存在内存数组中。写入完成并确认接收字节数等于声明大小后关闭流，并向发送方确认完成。

如果用户拒绝选择位置、磁盘写入失败、连接中断或任一方取消：

- 终止当前文件传输。
- 中止写入流，使未完成文件不作为成功文件保留。
- 双方显示明确的失败或取消状态。
- 重新发送时从头开始，不支持断点续传。

## 流量控制

接收端只有在分片成功写入磁盘后才累计已写入字节。发送端继续使用 DataChannel `bufferedAmount` 背压，并增加接收端写入确认窗口，避免磁盘写入速度慢于网络时浏览器持续堆积内存。

进度以已确认写入磁盘的字节为准。速度和预计剩余时间继续使用整数显示。

## 兼容性检测

大文件接收前同时检查：

- 非移动设备。
- Chrome 或 Microsoft Edge。
- `window.showSaveFilePicker` 可用。
- 页面运行在 HTTPS 安全上下文。

任一条件不满足即拒绝大文件，不降级到内存接收。

## 测试

- 微信 User-Agent 被正确识别并阻断核心操作。
- 普通浏览器不显示微信阻断页。
- 小于 512MB 的文件继续使用内存接收流程。
- 512MB 至 10GB 的文件进入磁盘流式流程。
- 超过 10GB 的文件在发送前被拒绝。
- 不支持磁盘写入的浏览器拒绝大文件。
- 取消、磁盘写入失败和连接中断都会中止文件并同步状态。
- 多文件传输时大小文件可按各自模式独立处理。
